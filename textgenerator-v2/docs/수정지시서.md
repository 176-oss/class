# textgenerator-v2 수정 지시서 (Claude Code 작업용)

작성일: 2026-11-06 / 대상 저장소: `176-oss/class`, 폴더 `textgenerator-v2/`
이 파일 하나에 이번 수정사항이 모두 들어 있다. Claude Code는 이 파일을 처음부터 끝까지 읽고 작업한다.

사용 방법 (선생님용)
1. 이 파일을 저장소의 `textgenerator-v2/docs/수정지시서.md` 로 넣는다.
2. Claude Code에 다음 한 줄을 붙여 넣는다.
   `textgenerator-v2/docs/수정지시서.md 를 끝까지 읽고, 거기 적힌 순서와 규칙대로 작업해줘. 모르는 점이나 지시서와 코드가 충돌하는 점은 작업 전에 물어봐.`

## 작업 전 결정 사항 (2026-11-07, 선생님 답변)
- 글꼴: IBM Plex Sans KR 400/500/600을 `textgenerator-v2/lib/fonts/`에 내장한다 (OFL 1.1, 합계 약 1.3MB).
- SheetJS: 저장소 공용 `../lib/xlsx.full.min.js`를 그대로 쓴다. 0-2의 1번·8번 규칙의 예외로 둔다 (저장소 안 파일이라 외부 코드가 아님).

## 0. 너의 역할과 일하는 방식
너는 작은 개발 회사의 개발 책임자다. 일을 역할별로 나눠 서브에이전트에게 맡긴다.

| 담당 | 맡는 일 |
|---|---|
| 기획 담당 | 이 지시서를 읽고 `docs/contract.md` 변경안을 먼저 쓴다 (데이터 구조, 모듈, 함수 계약). 지시서와 기존 계약이 충돌하면 목록으로 정리해 나에게 묻는다 |
| 개발 담당 A | 1장 구글 드라이브 저장 구조, 4장 저장 버튼, 5장 API 키 |
| 개발 담당 B | 2장 내 스타일 참고자료, 3장 초안 바로 고치기 |
| 검수 담당 | 코드를 쓰지 않은 에이전트. 8장 완료 기준을 하나씩 확인하고 `docs/review.md`에 추가. 문제는 해당 담당이 고치고 다시 검수 |

작업 순서: 기획(계약) → 1장 → 4장·5장 → 2장 → 3장 → 검수. 1장이 나머지의 바탕이다.
브랜치: `feat/textgenerator-v2-drive-style` 하나에 커밋하고 PR을 만든다. main에 바로 합치지 않는다.

## 0-2. 절대 규칙 (모든 장에 적용)
1. `textgenerator-v2/` 밖의 파일은 수정하지 않는다. 출결 앱 코드가 필요하면 `textgenerator-v2/` 안으로 복사해 고쳐 쓴다 (폴더 사이 import 금지).
2. 학생 이름과 학번은 AI로 보내지 않는다. 메모, 스타일 예시, 다듬기 요청 모두 해당.
3. API 키는 백업 파일, 엑셀 내보내기, 콘솔, 오류 메시지에 절대 넣지 않는다. 드라이브에는 5장의 선택 기능을 켰을 때만, 정해진 필드에만.
4. 개발자 서버나 그 밖의 외부 주소로 데이터를 보내지 않는다. 연결 대상은 Google 로그인, Google Drive API, Gemini API뿐.
5. innerHTML 금지 (textContent, DOM 생성). 이모지와 장식 기호 문자 금지. 기존 디자인 토큰과 글꼴(IBM Plex Sans KR 하나) 유지.
6. 버튼 44px 이상, 키보드로 모든 기능, 포커스 보임, 알림은 aria-live.
7. 기존 테스트는 모두 계속 통과해야 한다.
8. 외부에서 코드를 불러오지 않는다. `<script src="https://...">`, CDN 라이브러리, 외부 글꼴 주소를 쓰지 않는다.
   - 엑셀 처리용 SheetJS 같은 라이브러리가 필요하면 파일을 `textgenerator-v2/lib/`에 넣고 상대 경로(`./lib/...`)로 불러온다.
   - 라이브러리 파일 맨 위의 저작권·라이선스 주석은 지우지 않는다. `lib/README.md`에 이름, 버전, 라이선스, 받은 곳을 적는다.
   - 글꼴(IBM Plex Sans KR)을 외부 주소에서 불러오고 있다면 파일을 저장소에 넣어 쓴다. 글꼴 라이선스가 허용하는지 확인하고, 막혀 있거나 용량이 크면 작업 전에 나에게 묻는다.
   - 유일한 예외는 구글 로그인 스크립트(`accounts.google.com/gsi/client`)다. 구글이 정한 방식이라 내려받아 쓸 수 없다.
   - 이유: 앱은 서버 없이 접속할 때마다 코드를 받아 실행하므로, 외부 코드가 바뀌면 사용자의 드라이브 데이터를 읽는 코드가 그대로 실행될 수 있다.
   - 작업을 시작할 때 지금 외부에서 불러오는 것이 무엇인지 목록을 먼저 보여 준다.

## 1장. 구글 드라이브를 원본으로 저장

### 1-1. 왜, 무엇을
- 지금은 IndexedDB에만 저장한다. 크롬의 '쿠키 및 기타 사이트 데이터' 삭제, 학교 PC 복원 프로그램, 다른 PC 사용에서 데이터가 사라진다.
- **구글 드라이브가 원본, IndexedDB는 임시 사본**으로 바꾼다. 사본을 남기는 이유는 두 가지다. 타자마다 드라이브에 올릴 수 없어 모아서 올리고, 인터넷이 끊겼을 때도 쓴 글을 지켜야 한다. 사본이 지워져도 다시 연결하면 드라이브에서 전부 돌아와야 한다.
- 출결 앱과 같은 OAuth 클라이언트 ID(`attendance/config.js`의 값을 `textgenerator-v2/config.js`로 복사)를 쓴다. 범위는 `https://www.googleapis.com/auth/drive.appdata` 하나. 같은 주소라 Google Cloud 설정 변경은 필요 없다.
- 파일 이름: 데이터 `sgb-data.json`, 자동 백업 `sgb-backup-YYYYMMDD.json`. 출결 파일과 겹치지 않는다.

### 1-2. 드라이브 데이터 파일 형식 (contract에 새 절로)
```js
{
  kind: 'sgb-v2-data', schemaVersion, updatedAt,
  students: [], classes: [], records: [],
  settings: { ...기기별 값 제외, updatedAt },
  styles: { ... },            // 2장
  secrets: null | { geminiKey, updatedAt },   // 5장, 선택 기능을 켰을 때만
  deleted: [{ store: 'students'|'classes'|'records', id, deletedAt }]
}
```
- 기기별 설정(`keyStorage`, `devFakeAI`, 공용 PC 옵션)은 드라이브에 올리지 않는다.
- 지금은 삭제 기록이 없어 다른 기기에서 지운 것이 되살아날 수 있다. 학생·반·기록을 지울 때 `deleted`에 남기고 90일 지나면 정리한다.
- `settings.updatedAt`을 추가하고 설정을 바꿀 때 갱신한다. 스키마 버전을 올리고 `migrate`를 추가한다.

### 1-3. 합치기 `js/core/sync-merge.js` (순수 함수, 테스트 대상)
`mergeData(local, remote)`
- 학생·반·기록: id별로 `updatedAt`이 늦은 쪽. 같으면 원격.
- 삭제 기록과 항목: 더 늦은 쪽이 이긴다.
- 기록의 `neis` 필드(확장프로그램이 쓰는 NEIS 입력 완료)는 따로 합친다: `doneAt`이 늦은 쪽. 본문이 이겼다고 `neis`를 잃으면 안 된다.
- `settings`, `secrets`: `updatedAt`이 늦은 쪽. 기기별 값은 항상 로컬.
- `styles`: 영역별 `updatedAt`이 늦은 쪽.
- 결과에 바뀐 수(새로 들어옴, 고쳐짐, 지워짐)를 함께 돌려준다.

### 1-4. `js/drive.js`
`attendance/drive.js`를 바탕으로: 토큰 받기(처음은 동의 화면, 이후 `prompt: 'none'` 조용한 재요청, 막히면 '구글 연결 확인' 배너에서 사용자가 눌러 다시), 파일 찾기, 메타데이터(version, modifiedTime)만 확인, 내려받기, 올리기(multipart), 오래된 자동 백업 정리.
- 토큰 보관: 기본 localStorage(약 1시간). 설정의 '공용 PC' 옵션을 켜면 sessionStorage에만.

### 1-5. `js/sync.js` 동기화 흐름
- 시작: IndexedDB 사본으로 먼저 화면을 그린다 → 연결되어 있으면 조용히 토큰 → 드라이브 파일 받기 → 합치기 → 사본 갱신 → 화면 갱신. 사본이 비어 있고 드라이브에 데이터가 있으면 '드라이브에서 학생 N명, 기록 N건을 불러왔습니다'.
- 저장: 지금처럼 IndexedDB에 바로 쓰고, 마지막 변경 3초 뒤 드라이브에 올린다. 탭이 숨겨지거나 닫힐 때(`visibilitychange`, `pagehide`) 기다리는 것이 있으면 바로 올린다.
- 올리기 전에 드라이브 메타데이터를 확인한다. 마지막으로 본 것과 다르면 먼저 받아 합친 뒤 올린다. 다른 기기나 확장이 고친 것을 덮어쓰지 않기 위해서다.
- 탭이 다시 보일 때와, 보이는 동안 5분마다 메타데이터를 확인한다. 바뀌었으면 받아 합친다.
- 오프라인이거나 실패하면 '연결되면 올립니다'로 두고 간격을 늘려 가며 다시 시도한다. 기다리는 변경 표시를 IndexedDB에 남겨 새로고침 뒤에도 올린다.
- 처음 연결할 때 브라우저와 드라이브 양쪽에 데이터가 있으면 요약(학생 수, 기록 수, 마지막 수정)을 보여 주고 고르게 한다: [합치기] / [드라이브 것만 쓰기] / [이 브라우저 것으로 드라이브 바꾸기]. 고르기 전에 양쪽을 자동 백업한다.
- 하루 첫 저장 때 `sgb-backup-YYYYMMDD.json` 자동 백업을 만들고 최근 7개만 둔다. 자동 백업에도 `secrets`는 넣지 않는다.

### 1-6. 화면
- 머리 줄 저장 상태: '구글 드라이브에 저장됨 14:05' / '저장 중' / '연결되면 올립니다' / '드라이브 연결 안 됨: 이 브라우저에만 저장'(경고색, 누르면 설정으로). 옆에 4장의 저장 버튼.
- 처음 실행: 학교급 설정 다음에 '구글 드라이브에 연결' 단계(추천). [나중에]를 골라도 연결 안 됨 배너는 계속 보인다.
- 설정의 '구글 드라이브' 카드: 연결 상태, [연결] [지금 동기화] [연결 끊기], '공용 PC' 옵션, [드라이브의 생기부 데이터 지우기](확인 2번).
- [연결 끊기]를 누르면 고른다: '이 브라우저 사본도 지우기'(공용 PC 추천) / '사본은 남기기'.
- 백업 화면: 드라이브 자동 백업 목록과 [이 백업으로 되돌리기]. 되돌리기 전에 현재 상태를 백업한다.
- 오류 문구
  - 401: '구글 연결이 만료되었습니다 [다시 연결]'
  - 403: '드라이브 접근 권한이 없습니다. 연결할 때 권한 상자를 체크했는지 확인하세요'
  - 학교 계정이 막혀 있을 때: 개인 계정을 쓰라는 안내

### 1-7. NEIS 옮기기 화면과 확장프로그램
- 드라이브에 연결되어 있으면 기본 안내를 '학교 PC 확장프로그램이 드라이브에서 완료 기록을 바로 가져갑니다'로 바꾼다.
- [확장프로그램으로 보내기]와 [NEIS 입력 파일 내려받기]는 '드라이브 없이 보내기' 아래로 옮겨 예비로 유지한다.
- 드라이브에서 받은 기록의 `neis` 필드로 입력 완료 표시를 갱신한다. 지금의 규칙대로 hash가 현재 최종본과 같을 때만 유효하다.
- contract에 '확장이 이 파일에 쓸 수 있는 범위'를 적는다.
  - 확장은 기록의 `neis` 필드만 쓸 수 있다.
  - 쓸 때는 받기 → 해당 기록의 `neis`만 바꾸기 → 올리기 순서이고, 올리기 직전에 파일 버전을 확인한다.
  - 확장은 `secrets`를 읽지 않는다.

## 2장. 내 스타일 참고자료
선생님마다 생기부 문체가 다르다. 예전에 쓴 글이나 마음에 드는 예시를 올려 두면, 초안이 그 문체를 따르게 한다.

### 2-1. 데이터 (드라이브 파일과 백업에 포함)
```js
styles = {
  updatedAt,
  areas: {
    // 키: common | autonomy | career | behavior | club | subject:<과목명>
    autonomy: { examples: [{ id, text, addedAt }], rules: '', aiRules: '', updatedAt }
  }
}
```

### 2-2. 화면 `#style` (주 메뉴 '내 스타일')
- 영역 탭: 공통, 자율·자치, 진로, 행동특성, 동아리, 교과세특(과목별).
- 예시 목록
  - 추가 방법: 붙여넣기, `.txt` 파일, `.xlsx`/`.csv` 파일(열 고르기)
  - 삭제 가능, 바이트 표시
  - 영역마다 최대 5개, 예시 하나는 그 영역의 바이트 한도 이하
- 직접 쓰는 '스타일 규칙' 칸 (예: '한 문장은 짧게', '평가어는 마지막 문장에 한 번').
- [AI로 스타일 정리]
  - 예시를 보내 문체 특징(문장 길이, 종결 어미, 구성 순서, 자주 쓰는 표현 유형)을 짧은 규칙 목록으로 받는다.
  - 결과를 고칠 수 있는 칸에 보여 주고, [이 규칙 쓰기]를 누르면 `aiRules`에 저장한다.
- 개인정보
  - 예시는 실제 학생 글일 수 있다. 넣을 때 명단에 있는 이름, 5자리 학번, 'n학년 n반 n번' 형태를 'OO'으로 바꾼다.
  - 바꾼 개수와 위치를 보여 주고, 선생님이 확인한 뒤 저장한다.
  - 화면에 '다른 학생 이름이나 알아볼 수 있는 내용은 지우고 넣으세요'를 안내한다.
  - AI로 보내기 직전에 한 번 더 가린다.

### 2-3. `js/core/style.js` (순수 함수, 테스트 대상)
- `maskExample(text, names)` → `{ text, replaced: [{from, index}] }`
- `buildStyleSummaryPrompt(examples)`
- `pickExamples(styles, area, subject)` → 규칙(직접 + AI 정리, 공통 + 영역) + 짧은 예시 1~2개. 요청을 가볍게 하고 소재 베끼기를 줄이기 위해 예시를 전부 보내지 않는다.
- `styleOverlap(draft, examples)` → 연속 6어절 이상 같은 부분 목록

### 2-4. 초안 만들기에 적용

  - 적용 중인 규칙을 한 줄로 요약해 보여 줌

## 3장. 초안 그 자리에서 고치기
지금은 초안 후보가 읽기 전용이라 '초안 칸에 저장'을 한 뒤에야 고칠 수 있다.

- 후보 카드 본문을 textarea로 바꿔 바로 고칠 수 있게 한다.
  - 고치는 즉시 바이트를 다시 계산하고, 한도를 넘으면 경고색으로 표시한다.
  - 고친 후보는 `candidates`에 저장해 새로고침해도 남게 하고, '고침' 표시를 붙인다.
- 카드 버튼: [초안 칸에 저장] [최종본 끝에 붙이기] [처음 상태로](그 후보의 AI 원문으로 되돌림).
- [AI에게 다듬기 요청]
  - 카드 아래에 한 줄 입력칸을 둔다 (예: '더 짧게', '리더십 부분을 줄이고 탐구 과정을 앞으로').
  - 빠른 칩: [더 짧게] [더 자세히] [문장 나누기] [평가어 줄이기]
  - 보내는 것: 현재 후보 글, 요청, 메모, 스타일 규칙. 이름과 학번은 보내지 않는다.
  - '메모에 없는 사실을 더하지 않는다' 원칙을 유지한다.
  - 결과는 같은 카드의 새 판으로 넣고, [이전 판]으로 되돌릴 수 있게 한다. 판은 카드당 최근 3개까지.
- 후보 데이터 구조 변경: `candidates`를 `[{ original, text, versions: [], edited }]`로 바꾼다. contract와 migrate에 반영한다.
- 완료(done) 기록은 지금처럼 최종본 붙이기를 막는다.
- 접근성: 각 textarea에 '후보 n' 라벨을 달고, 바이트 표시는 `aria-live="polite"`로 한다.

## 4장. 구글 드라이브에 저장 버튼
- 머리 줄 오른쪽, 저장 상태 글 옆에 항상 보이는 [구글 드라이브에 저장] 버튼을 둔다 (주 버튼 스타일, 44px).
  - 연결됨: 누르면 기다리는 변경을 자동 저장 대기와 상관없이 바로 올린다. 기록, 명단, 반, 설정, 스타일이 모두 들어간다.
    - 끝나면 '구글 드라이브에 저장했습니다 14:05' 토스트를 띄우고 상태를 갱신한다.
    - 실패하면 이유와 [다시 시도]를 보여 준다.
    - 바뀐 것이 없으면 '이미 저장되어 있습니다'.
  - 연결 안 됨: 같은 자리에 [구글 드라이브 연결]로 보이고, 누르면 연결한 뒤 바로 저장한다.
  - 올리는 중에는 비활성 + '저장 중'.
- 설정 화면 맨 아래에도 [설정을 구글 드라이브에 저장]을 둔다 (같은 동작). 설정을 바꾸면 버튼 위에 '저장 안 된 설정이 있습니다'를 표시한다.
- 휴대폰 폭에서는 머리 줄 버튼을 드라이브 아이콘(단색 SVG) + `aria-label`로 줄이되 44px는 유지한다.

## 5장. API 키를 드라이브에 저장 (선택 기능)

### 5-1. 보안 검토 결론 (구현 근거)
**선택 기능으로 넣어도 된다.** 기본값은 끔이고, 결제가 연결되지 않은 무료 키를 쓰는 것이 조건이다.
- 앱 전용 폴더는 드라이브 목록에 보이지 않고 공유되지 않는다. 같은 OAuth 클라이언트로 `drive.appdata` 권한을 받은 앱만 읽을 수 있다.
- 같은 파일에 이미 학생 이름과 생기부 글이 있다. 키가 같은 보호(구글 계정 보안) 아래 들어갈 뿐 보호 수준이 낮아지지 않는다.
- 남는 위험과 대응

| 위험 | 대응 |
|---|---|
| 결제 연결된 키가 새면 요금 발생 | 무료 키만 쓰라고 안내 |
| 키는 지울 때까지 유효 (토큰은 약 1시간) | 키 제한 안내: API 제한 'Generative Language API'만, 웹사이트 제한 `https://176-oss.github.io/*`. 의심되면 AI Studio에서 삭제 후 재발급 |
| 공용 PC에 토큰이 남음 | 공용 PC 옵션이 켜져 있으면 키 드라이브 저장 비활성 |
| 같은 주소(176-oss.github.io)의 다른 앱에 XSS가 생기거나 외부 코드가 바뀌면 키와 학생 데이터가 함께 위험 | innerHTML 금지 유지, 외부 코드는 저장소에 내장(0-2의 8번), 학생 제작 코드는 별도 주소에 둠 |
| 백업 파일이 밖으로 돌면 키도 샘 | 백업·엑셀·자동 백업에 키를 넣지 않음 |

- 암호화는 하지 않는다. 풀 열쇠를 같은 브라우저에 두면 의미가 없고, 매번 비밀번호를 받으면 '다른 PC에서 다시 입력하지 않기'라는 목적이 사라지기 때문이다.

### 5-2. 구현
- 설정의 API 키 칸 아래에 체크 '구글 드라이브에도 저장 (다른 PC에서 다시 입력하지 않아도 됨)'을 둔다. 기본은 끔.
- 체크를 켤 때 확인 상자를 띄운다: 무료 키 사용, 키 제한 방법, 공용 PC에서는 권하지 않음, 의심되면 재발급. [켜기] [취소].
- 저장 위치는 드라이브 파일의 `secrets = { geminiKey, updatedAt }`이다 (settings와 분리).
- 다른 PC에서 연결했을 때 `secrets`에 키가 있으면 묻는다: '드라이브에 저장된 API 키를 쓸까요? [쓰기] [이 PC에서는 쓰지 않기]'.
- 체크를 끄면 드라이브의 `secrets`를 비운다. [키 지우기]는 이 브라우저와 드라이브 양쪽에서 지운다.
- 공용 PC 옵션이 켜져 있으면 체크를 비활성하고 이유를 표시한다.
- Gemini 요청은 지금처럼 `x-goog-api-key` 헤더로 보낸다 (URL 금지).
- README에 키 제한 설정 방법을 그림 없이 단계로 적는다.

## 6장. 확장프로그램 쪽 메모 (이번 작업 범위 아님)
