# 생기부 NEIS 자동 입력 확장프로그램 기획 초안 (v0.1)

작성일: 2026-11-06 / 단계: 기획 초안 (나이스 생기부 화면 구조 분석 전)
관련 문서: `생기부-작성도우미-업그레이드-기획서.md`, `출결관리-앱-기획서.md`, `나이스-출결화면-구조-분석.md`

## 0. 한 줄 요약
생기부 작성 도우미(웹앱)에서 '완료'로 표시한 글을, 학교 PC 크롬에서 나이스 생기부 입력 화면을 열면 확장프로그램이 화면을 알아보고 학생별로 자동으로 채운다. 선생님이 사이드 패널에서 전체를 확인한 뒤에만 저장하고, 마감·확정 계열 버튼은 절대 누르지 않는다.

## 1. 출결 확장프로그램에서 그대로 쓰는 것
현재 출결 확장(v0.4.2)의 구조를 바탕으로 한다.

| 출결 확장 | 생기부에서 |
|---|---|
| `content/bridge.js` (격리 환경 ↔ 페이지, nonce 채널) | 그대로 사용 |
| `content/page.js` (MAIN world, eXbuilder6 `cpr` 앱 인스턴스 찾기, 컨트롤 조회, 실제 클릭, 확인창 처리, 표 스크롤, 금지 버튼 차단) | 화면과 무관한 부분을 `content/neis-core.js`로 분리해 함께 사용. 생기부 전용 동작은 `content/sgb-page.js` |
| 사이드 패널 (입력 시작, 멈추기, 확인 단계, 이대로 저장, 작업 기록) | 같은 흐름과 화면 규칙. 생기부 탭 추가 |
| 화면 감지 (`app.id`에 `mis_srgaa02_m02` 포함) | 생기부 화면별 `app.id`로 감지 (2절에서 확인) |
| 저장 규칙 (확인창 문구가 정확히 "저장하시겠습니까?"일 때만 확인, "저장했습니다." 알림 확인 후 결과 검증) | 같은 원칙. 문구는 화면에서 다시 확인 |
| 고정 확장 ID, 버전 알림, 가상 나이스 화면 | 그대로. 가상 생기부 화면 추가 |

### 결정할 것: 확장을 하나로 할지 둘로 할지
- 추천: **같은 확장에 '생기부' 기능을 추가** (이름 '교사 업무 도우미 - 나이스 연동' 등으로 변경, 버전 0.5.0).
  - 장점: 학교 PC 설치 한 번, 공통 코드 한 벌, 확장 ID와 업데이트 알림 유지.
  - 위험: 출결 기능이 깨질 수 있음 → 공통 코드를 분리할 때 출결 테스트를 먼저 통과시키고, 생기부 코드는 별도 파일로만 추가.
- 대안: 별도 확장 '생기부 도우미 - 나이스 연동'. 공통 코드는 복사. 출결에 영향 없지만 설치가 두 번.

## 2. 먼저 할 일: 나이스 생기부 화면 구조 분석 (읽기 전용)
출결 때처럼 실제 화면에서 직접 확인한다. 아래 화면 이름과 메뉴 위치는 아직 확인하지 않은 가정이다.

| 영역 | 예상 화면 (확인 필요) | 입력하는 사람 |
|---|---|---|
| 자율·자치, 동아리, 진로 | 학교생활기록부 > 창의적 체험활동 특기사항 입력 | 담임, 동아리 담당 |
| 행동특성 및 종합의견 | 학교생활기록부 > 행동특성 및 종합의견 | 담임 |
| 교과세특 | 교과학습발달상황 > 세부능력 및 특기사항 (반, 과목, 학기 선택) | 교과 담임 |

화면마다 기록할 것 (출결 분석 문서와 같은 형식, `나이스-생기부화면-구조-분석.md`)
1. 앱 인스턴스 `app.id` (화면 감지용)
2. 조회 조건 컨트롤과 데이터맵: 학년도, 학기, 학년, 반, 과목, 영역 (값 형식 포함)
3. 학생 표: 그리드 id, 데이터셋 이름, 컬럼 이름 (번호, 이름, 특기사항 본문, 바이트, 입력 상태 등). 생년월일 같은 개인정보 컬럼은 읽지 않음
4. 본문 입력 방식: 표 칸에 바로 쓰는지, 행을 고르면 아래 입력칸이 열리는지, 팝업인지. 컨트롤 종류(textarea, inputbox)와 id
5. 값을 넣는 확인된 방법: 데이터셋 `setValue`가 되는지, 컨트롤 `value` 대입 후 어떤 이벤트가 필요한지, 실제 키 입력이 필요한지
6. 나이스 자체 바이트 표시와 초과 시 동작
7. 저장 버튼 id, 클릭 처리 순서, 확인창·알림 문구, 저장 성공 판정 방법 (행 상태 값)
8. 누르면 안 되는 버튼 목록 (마감, 확정, 일괄 삭제, 가져오기, 출력, 반영 등)과 id
9. 이미 입력된 글이 있을 때 표시, 행 상태 값 (변경 없음, 수정됨)
10. 학생 수가 많을 때 스크롤 처리

분석은 읽기 전용으로만 한다. 값을 바꿔 보는 시험은 저장하지 않고 [조회]로 되돌리는 방식으로 한 명만.

## 3. 데이터 넘기기 (웹앱 → 확장)
웹앱은 `176-oss.github.io/class/textgenerator-v2/`의 브라우저 저장소에 있고, 확장은 따로 저장한다. 구글 드라이브 없이 넘긴다.

1. 기본: 학교 PC 크롬에서 웹앱을 연다 → [NEIS 옮기기] 화면의 **[확장프로그램으로 보내기]**를 선생님이 누른다.
   - 확장의 콘텐츠 스크립트(`content/sgb-bridge-app.js`, 웹앱 주소에서만 실행)가 `postMessage`로 받는다. 출처(origin)와 메시지 형식을 검사하고, 받은 뒤 '받았습니다 N명' 응답을 보낸다.
   - 확장은 `chrome.storage.local`에 저장한다. 이 PC 밖으로 보내지 않는다.
2. 예비: 웹앱에서 'NEIS 입력 파일'(JSON)을 내려받아 사이드 패널에서 [파일 불러오기].
3. 입력 결과(완료 표시)는 반대로, 학교 PC에서 웹앱을 열면 확장이 '입력 완료 목록'만 웹앱에 알려 주고 웹앱이 상태를 갱신한다.

보내는 데이터 (초안)
```json
{
  "kind": "sgb-neis-batch",
  "version": 1,
  "createdAt": "2026-11-20T10:00:00+09:00",
  "schoolYear": 2026,
  "semester": 2,
  "items": [
    {
      "id": "30503|autonomy",
      "studentId": "30503",
      "grade": 3, "classNo": 5, "no": 3,
      "name": "박OO",
      "area": "autonomy",
      "subject": null,
      "text": "학급 회의를 세 차례 진행하며 ...",
      "bytes": 1032,
      "hash": "sha256 앞 16자리"
    }
  ]
}
```
- `area`: `autonomy`(자율·자치), `club`(동아리), `career`(진로), `behavior`(행동특성), `subject`(교과세특, `subject`에 과목명)
- 이름은 나이스 표와 대조용으로만 쓴다. 상태가 '완료'인 글만 보낸다.
- `hash`로 같은 글을 두 번 입력하거나, 웹앱에서 고친 뒤 옛 글을 입력하는 일을 막는다.

## 4. 입력 흐름 (출결과 같은 모양)
1. 선생님이 나이스 생기부 입력 화면을 연다 → 사이드 패널 '나이스 생기부 화면 감지됨: 창의적 체험활동, 2026학년도 2학기 3학년 5반, 자율·자치'
2. 조회 조건(학년도, 학기, 반, 과목, 영역)이 불러온 데이터와 맞는지 확인. 다르면 '나이스 화면은 통합과학 3-6, 불러온 글은 3-5' 식으로 알리고 시작 버튼을 막는다. 조회 조건은 확장이 바꾸지 않고 선생님이 바꾼다 (첫 버전).
3. [입력 시작] → 이 화면 조건에 맞는 글을 학생 순서대로 자동 입력
   - 학생 행 찾기: 번호 + 이름이 모두 맞을 때만
   - 본문 넣기 → 나이스 값을 다시 읽어 보낸 글과 정확히 같은지 비교
   - 학생 사이 멈춤 없음. 진행률과 작업 기록 표시
   - 자동 입력에서 빼고 '직접 확인이 필요한 학생' 목록으로: 나이스에 이미 다른 글이 있는 학생, 이름 불일치, 바이트 초과, 나이스에 없는 학생, 같은 학생 글이 2개 이상
4. **선생님 확인 단계**: 사이드 패널에 학생별 '보낸 글 / 나이스 현재 값 / 상태'. 입력한 행을 나이스 표에서 강조. 이미 글이 있던 학생은 두 글을 나란히 보여 주고 [이 학생은 덮어쓰기]를 선생님이 고를 때만 다시 입력
5. [확인 완료 · 저장] → 바뀐 행이 모두 이번에 확장이 입력한 행인지 검사 → 저장 목록 표시 → [이대로 저장] → 나이스 [저장] → 확인창 문구 확인 후 [확인] → 알림 확인 → 저장 결과 검증 (행 상태, 값 유지)
6. 저장된 글은 '입력 완료'로 표시. 다음 조건(다른 영역, 다른 반)은 선생님이 나이스에서 조회 조건을 바꾸면 다시 감지
- 언제든 [멈추기]. 저장 전이면 나이스 [조회]로 되돌릴 수 있음을 안내. 저장 버튼을 누른 뒤에는 멈추기 없음

## 5. 안전 규칙
- 확장이 누르는 것: 학생 행 선택, 본문 입력, 선생님이 [이대로 저장]을 누른 뒤의 [저장]과 정해진 문구의 확인창·알림
- 절대 누르지 않는 것: 마감, 확정, 마감취소, 일괄 삭제, 일괄 반영, 가져오기, 출력, 조회 조건 변경, 그 밖의 모든 확인창 (2절에서 id를 확인해 차단 목록에 넣음)
- 이미 글이 있는 학생은 기본으로 건너뜀
- 바이트 초과 글은 입력하지 않음 (웹앱과 같은 계산 + 나이스 자체 표시로 이중 확인)
- 콘솔과 작업 기록에 학생 이름과 본문을 남기지 않음 (번호만)
- 학생 이름과 글은 이 PC의 `chrome.storage.local`에만. [이 PC의 생기부 데이터 모두 지우기] 제공
- 학교 정책: 나이스에 확장프로그램으로 입력하는 것이 학교(교육청) 지침에 맞는지 먼저 확인

## 6. 사이드 패널 화면 (생기부 탭)
- 위: 감지된 화면과 조건, 불러온 데이터 요약(학년도·학기, 영역별 N명, 받은 시각)
- [웹앱에서 받기 안내] [파일 불러오기]
- 현재 조건에 맞는 학생 목록: 번호, 이름, 바이트, 상태(대기 / 입력됨 / 직접 확인 / 저장됨)
- [입력 시작] [멈추기] → 확인 단계 → [확인 완료 · 저장] → 저장 목록 → [이대로 저장]
- [작업 기록 보기]
- 디자인: 출결 확장과 같은 토큰. 이모지 없음, 글꼴 하나

## 7. 개발 단계와 역할
| 단계 | 담당 | 산출물 |
|---|---|---|
| 0. 화면 분석 | 사용자 + 분석 담당 | `나이스-생기부화면-구조-분석.md` (2절 항목) |
| 1. 기획 확정 | 기획 담당 | 이 문서 v0.2 (분석 반영, 확장 하나/둘 결정) |
| 2. 공통 코드 분리 | 연동 개발 담당 | `neis-core.js`, 출결 테스트 전부 통과 |
| 3. 생기부 기능 | 연동 개발 담당 | `sgb-page.js`, 사이드 패널 탭, 웹앱 받기 스크립트, 가상 생기부 화면 |
| 4. 웹앱 연결 | 앱 개발 담당 | 웹앱 [확장프로그램으로 보내기], 입력 완료 반영 |
| 5. 검수 | 품질 담당 | 가상 화면 시험, 안전 규칙 점검, 출결 회귀 시험 |
| 6. 학교 시험 | 사용자 | 학생 1명, 저장 없이 → [조회]로 되돌리기 → 1명 저장 → 여러 명 |

## 8. 열린 질문
1. 확장 하나로 합칠지, 따로 만들지
2. 나이스 생기부 화면 메뉴 위치와 화면 이름 (2절)
3. 이미 글이 있는 학생: 건너뛰기만 할지, 선생님이 고르면 덮어쓰기까지 허용할지
4. 교과세특은 학기별로 따로 입력하는지, 과목 선택과 학기 선택이 어떻게 되는지
5. 학교(교육청) 지침상 확장프로그램 자동 입력 허용 여부
