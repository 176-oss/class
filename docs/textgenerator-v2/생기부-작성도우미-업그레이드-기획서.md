# 생기부 작성 도우미 업그레이드 기획서 (v0.1)

작성일: 2026-11-06 / 단계: 기획, 미리보기 시안 확인 중
관련 문서: `생기부-작성도우미-분석과-적용안.md` (첨부 도구 분석)

## 0. 결정 사항
- 구글 시트 방식은 하지 않는다. 다른 선생님이 시트 사본, Apps Script 권한 승인을 거치기 어렵기 때문.
- 지금 쓰는 `176-oss.github.io/class/textgenerator/`(단일 HTML, Gemini)를 바탕으로 업그레이드한다.
- 기존 페이지는 그대로 두고 새 폴더(`textgenerator-v2/` 가칭)에 만든다. 써 보고 마음에 들면 기존 주소로 바꾼다.
- 첨부 도구(v1.14)는 2차 저작물 금지라서 코드·프롬프트·사전은 가져오지 않는다. 기능 아이디어만 참고하고 모두 새로 만든다.
- 디자인: 꿀색 계열 3색(#6B4410, #C98A1B, #FBEFD5) + 경고 빨강 #B42318, 글꼴 IBM Plex Sans KR 하나, 이모지 없음.

## 1. 지금 버전의 한계
| 항목 | 지금 | 문제 |
|---|---|---|
| 학생 | 엑셀 한 장의 `학생_식별자` | 반 구분, 담임·교과·동아리 구분 없음 |
| 저장 | 없음 (새로고침하면 사라짐) | 결과를 엑셀로 받아 따로 관리해야 함 |
| 일괄 생성 | 활동내용만 프롬프트에 넣음 | 성향, 성취기준, 분량 조건이 빠짐 |
| 검사 | 글자 수만 | 바이트 한도, 금지 표현, NEIS 깨지는 문자 검사 없음 |
| 키 | 주소창 `?key=`로 전송 | 로그에 남을 수 있음 |
| 화면 | 결과 표에 `innerHTML`로 AI 답을 그대로 넣음, 이모지 | 안전성, 디자인 원칙 |

## 2. 업그레이드 후 구성
설치 없는 웹페이지 하나(GitHub Pages). 데이터는 그 브라우저(IndexedDB)에 저장하고, 백업 파일로 옮긴다.

| 화면 | 내용 | 첨부 도구에서 참고한 점 |
|---|---|---|
| 명단 | 내가 맡은 반(담임 / 교과 / 동아리)과 5자리 학번 명단. 엑셀 양식, NEIS 출석부 파일, 붙여넣기로 등록. 학번 5자리 검사 | NEIS 출석부 그대로 올리기, 머리글 자동 찾기 |
| 작성 | 반 고르기 → 그 반의 영역 탭 → 학생 표(메모, AI 초안, 최종본, 바이트, 상태, 검사) + 오른쪽 패널 | 3단 편집기를 표 + 패널로 단순화 |
| 오른쪽 패널 | 메모 → 초안 → 검사 → NEIS 4단계. 목표 분량(간결/표준/충실), 드러낼 모습 칩 | 분량 3단계, 메모 기반 초안 |
| 일괄 초안 | 고른 학생이나 미작성 학생만. 간격 두고 하나씩, 중단과 이어서 하기. 완료 학생은 건너뜀 | 원본에 없는 기능 (원본은 한 명씩) |
| 현황 | 학생 x 영역 표, 칸마다 바이트만큼 채움. 초과·금지 표현 빨간 테두리. 칸 누르면 작성으로 | 대시보드 |
| NEIS 옮기기 | 완료 학생만 한 명씩 [복사] → [옮김, 다음]. 진행률 | NEIS 입력 도우미 |
| 백업 | 백업 파일 내보내기·가져오기, 영역별 엑셀 내보내기, 가져오기 전 미리보기 | JSON 백업, 엑셀 내보내기 |
| 설정 | API 키, 학교급, 영역별 한도, 금지 표현 목록 편집 | 영역 표, 금지어 관리 |

## 3. 데이터
- 학생: 학번(5자리, 문자열) + 이름. 학번이 같으면 같은 학생.
- 반: 이름, 종류(담임/교과/동아리), 영역 목록, 학번 목록. 교과반은 과목명 + 교과세특.
- 기록: 학번 + 영역(+ 과목) 하나에 메모, 초안(여러 개), 최종본, 상태(미작성/메모/초안/완료), 수정 시각.
- 상태 '완료'는 일괄 생성과 가져오기에서 덮어쓰지 않는다.
- 영역 한도 기본값(고·중, 확인 필요): 교과세특·자율·자치·진로·동아리 1,500 byte, 행동특성 900 byte. 바이트는 한글 3, 영문·숫자·공백 1.

## 4. AI
- Gemini를 브라우저에서 직접 호출 (지금과 같은 방식). 키는 `x-goog-api-key` 헤더로 보냄.
- 키 저장: '이 브라우저에 저장' / '이번에만 사용' 선택. 백업 파일에는 넣지 않음.
- 보내는 것: 메모, 영역, 과목, 목표 분량, 고른 성향. 이름과 학번은 보내지 않음. 메모 안의 명단 이름은 보내기 전에 지움.
- 프롬프트 원칙(새로 작성): 메모에 있는 사실만, 지어내지 않음, 명사형 종결, 학생 호칭 없음, 쓸 내용이 부족하면 정해진 문장으로 답함. 메모 분량에 따라 분량 지시를 바꿈.
- 답은 JSON으로 받고, 화면에는 글자로만 넣음(`textContent`).
- 모델 목록은 설정에서 고르고, 한도 초과·혼잡이면 다음 모델로 넘어감. 오류는 쉬운 한국어로.
- AI 결과는 초안 칸에만 저장. 최종본은 선생님이 [최종본 끝에 붙이기]로 직접 옮김.

## 5. 검사 (AI 없이 항상)
- 바이트: 95% 이상 '한도에 가까움', 넘으면 '초과'
- 금지 표현: 우리가 기재요령 원문을 보고 만든 목록(분류, 근거, 바꿀 표현, 적용 영역). 단어 경계 고려
- NEIS에서 깨지는 문자(둥근 따옴표 등)와 연속 공백: [정리] 버튼
- 다른 학생과 90% 이상 같은 글이면 알림
- 경고는 저장을 막지 않음

## 6. 개발 단계와 역할
| 단계 | 담당 | 산출물 |
|---|---|---|
| 1. 기획 | 기획 담당 | 이 문서 |
| 2. 디자인 | 디자인 담당 | 미리보기 시안(완료), 토큰 CSS |
| 3. 개발 A | 화면 개발 담당 | 명단, 작성, 현황, 백업 화면과 저장소 |
| 4. 개발 B | AI·검사 담당 | 프롬프트, 일괄 생성, 검사 엔진, 금지 표현 목록 초안 |
| 5. 검수 | 품질 담당 | 기능 점검, 개인정보 점검(이름 미전송 확인), 접근성 |
| 6. 배포 | 사용자 | `textgenerator-v2/`에 올려 시험 → 마음에 들면 기존 주소 교체 |
