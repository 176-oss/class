# 나이스 생기부 입력 화면 구조 분석 (v0.1, 읽기 전용 기록 기준)

작성일: 2026-11-10 / 방법: 생기부 확장(sgb-extension 0.2.0)의 [화면 구조 기록]으로 수집. 앱 id, 컨트롤 id·종류, 버튼 글자, 데이터 컬럼 이름, 행 개수만 읽음. 학생 이름, 생년월일, 본문 값은 읽지도 옮기지도 않음.
관련 문서: `생기부-NEIS-확장프로그램-기획초안.md` 2절(항목 1~10), `sgb-extension/README.md`

## 0. 수집 상황
- 주소: `https://goe.neis.go.kr/jsp/main.jsp` 한 페이지 안에서 모든 화면이 MDI 탭으로 열린다. 구조 기록은 열려 있는 탭 전체를 한꺼번에 기록한다(누적). 그래서 "자율", "진로", "행동특성" 기록 3개에 같은 화면들이 모두 들어 있었다.
- 기록은 5번 했다: 자율, 진로, 행동특성및종합의견, 과목별세부능력및특기사항, 동아리. 화면을 열 때마다 앱이 목록 끝에 붙으므로, 각 기록에서 **마지막에 나오는 부모 화면**(바로 뒤에 붙는 출결 `...m03`, `udc/...` 같은 부품은 제외)이 그때 사용자가 가리킨 화면이다. 5개 기록 모두 이 규칙으로 아래 app.id와 일치했다.
- 화면 제목 글자(`optTit`)와 메뉴 경로는 값을 읽지 않아 확인하지 못했다.
- 한 번 더 확인할 것은 7절.

조회 조건은 `dmSearch`(데이터맵)에 있고 화면의 콤보는 `udc.sw.swc.udcSwcAuth`(공통 부품, 각자 `dsAuth`: `cd`, `nm`)이다.

| 진로 | `cmbAyr`, `cmbDghtCrseScCd`, `cmbGrd`, `cmbClsCd` | 자율과 같음 |
| 동아리 | `cmbAyr`, `cmbClubActDptClsCd` | `ayr`, `sem`, `grd`, `clsCd`, `actScCd`, `clubActDptCd`, `clubActDptClsCd`, `clubActDptScCd` |
| 행특 | `cmbAyr`, `cmbDghtCrseScCd`, `cmbOrdGrd`, `cmbClsCd` | `ayr`, `sem`, `grd`, `dghtCrseScCd`, `clsCd`, `actScCd`, `classFinYn` |
| 교과세특 | `udcswcauth1`~`udcswcauth6` (학년도, 학기, 주야, 학년, 이수구분, 교실 순으로 보임) | `ayr`, `sem`, `dghtCrseScCd`, `grd`, `sbjtCd`, `sbjtNm`, `etbSbjtCd`, `etbClrmCd`, `osuCd`, `orgaCd` |

- 이 값들은 `dmSearch`가 아니라 콤보 `dsAuth`나 `dmSwcIndctInfo`에서 읽는 편이 안전할 수 있다. 어느 쪽이 조회 직후 값을 정확히 담는지 확인 필요.

## 4. 본문 입력 방식 (항목 4, 5)
- 표 아래에 큰 입력칸(textarea)이 하나 있다: 자율, 진로, 동아리 `txaSpeclActSpablMteCn`, 행특 `txaGnrlz`, 교과세특 `txa1`, `txa2`. 행을 고르면 그 입력칸에 내용이 열리는 방식으로 보인다. 입력칸 옆에 바이트 표시 부품 `udcdatabytececk1`(교과세특은 1~3)이 있다.
- 표 칸을 직접 고치는지(그리드 셀 편집), 입력칸에 쓴 것이 데이터셋에 언제 반영되는지(입력 중, blur, 행 이동)는 구조 기록만으로 알 수 없다. 읽기 전용 시험(7절)이 필요하다.
- 따라서 `input.mode`는 아직 정하지 못했다. 후보: ①데이터셋 `setValue` ②행 선택 + textarea 값 대입 + 이벤트. 가상 화면은 ①만 시험했다.
- 값을 넣었을 때 데이터셋 행 상태(수정됨)가 바뀌는지, 화면에 표시되는 바이트가 따라 바뀌는지도 7절에서 확인한다.

## 5. 바이트 (항목 6)
- `udcdatabytececk*`는 컨트롤이 없고 `subOnLoad` 서브미션만 있다. 한도는 서버에서 받아 오는 것으로 보이며(`dsExMessage`에도 메시지 74~79개) 화면에서 표시한다.
- `length` 컬럼은 NEIS가 계산한 길이(바이트 또는 글자 수)로 보인다. 어느 쪽인지, 줄바꿈이 1인지 2인지는 모른다.
- 교과세특은 `inputCanLeng`(입력 가능 길이), `inputLen`(입력된 길이), `othSemInputLen*`(다른 학기 입력 길이)가 있어 학기 합산 한도가 있는 것으로 보인다. 웹앱의 영역별 한도(1500)와 같은지 확인 필요.
- 확인 방법(읽기 전용): 이미 글이 있는 행 한 개를 골라 `length` 값을 읽고 우리 계산 결과와 비교한다.

## 6. 버튼, 저장, 금지 (항목 7, 8, 9)
### 저장
| 화면 | 저장 버튼 | 저장 서브미션 |
|---|---|---|
| 자율, 진로, 동아리 | `btnSave` (글자 "저장") | `subSaveScrgRec` |
| 행특 | `btnSave` | `subSaveScrgRec` |
| 교과세특 | `btnSave` | `subSave1`, `subSave2` (둘로 나뉨: 교과세특과 영재 기록으로 보임) |
- 저장 확인창과 알림 문구, 알림을 띄우는 컨트롤은 구조 기록에 없다. 문구는 `dsExMessage`(messageId, messageDiv)에 있을 가능성이 높다. 실제 문구는 선생님이 저장할 때 한 번 보고 알려 주셔야 한다(7절).
- 저장 성공 판정: 행 상태가 "변경 없음"으로 돌아오는지(출결 확장과 같은 방법). 확인 필요.

### 확장이 눌러도 되는 버튼 (허용 목록)
- 현재 후보는 `btnSave` 하나뿐이다. 조회(`btnSearch`)는 확장이 누르지 않고 선생님이 누른다.

### 절대 누르지 않는 버튼 (차단 목록)
같은 화면 안에서 눈에 띄는 위험 버튼은 모두 차단 목록에 넣는다.
- 지우기: `btnDelete`("삭제")
- 한꺼번에 바꾸기: `btnBndeSave`("일괄적용"), `btnChrsChg`("문자열바꾸기")
- 가져오기: `btnExcelUpload`("엑셀업로드"/"엑셀올리기"), `btnFileUpld`
- 내려받기와 출력: `btnExcelDwld`, `btnFileDwld`, `btnOtpt`, `btnPrint`("출력")
- 학생부 반영: `btnScrgRflt`("학생부 반영/취소"), `btnScrgRfltAll`("학생부 일괄반영"), `btnScrgRfltAllCen`("학생부 일괄반영취소") (동아리)
- 이수시간: `btnIsuHr`("이수시간반영") (자율, 진로, 동아리)
- 조회성 팝업: `btnCoseInfo`("진로정보조회"), `btnObsvList`("관찰내용조회")
- 출결 쪽 마감: `btnDdln`("마감", "출결마감"), `btnDdlnCancel`("마감취소")
- 글자 없는 버튼 `btnEntrJnt`, `btnExpa`, `btnDcr`, `btn3`, `btnAntiExpa`: 용도를 모르므로 차단
- 원칙: 차단 목록은 보조 안전망이고, 실제 보호는 "허용 목록 밖은 모두 거부"이다.

### 마감 상태 (확장이 입력하면 안 되는 경우)
- `optDdln`(출력 컨트롤, 마감 표시), 데이터맵 `dmScrgDdln`: `scrgClsDdlnYn`(학급 마감), `scrgDdlnCfmtnYn`(확정), `coaDdlnYn`, `ddlnYn`, `ddlnInfoCn`. 행특은 `dsScrgRec.ddlnYn`, `msDdlnYn`. 이 값이 Y이면 입력과 저장을 거부해야 한다. 값은 7절의 추가 기록으로 확인한다.

## 7. 아직 모르는 것과 다음 읽기 전용 기록
구조 기록은 값을 읽지 않으므로 아래는 모른다. 이름·본문이 아닌 값만 읽는 확장 기능(개발 필요)과, 선생님이 눈으로 보고 알려 주실 것으로 나눈다.

확장의 [화면 구조 기록]을 늘려 읽을 것(개인정보 아님):
1. 화면 제목 `optTit`의 글자, 메뉴 경로 `grpMenuPath`
2. `dmSearch`의 현재 값: `ayr`, `sem`, `grd`, `clsCd`, `actScCd`, (교과세특) `sbjtCd`, `sbjtNm`
3. 각 콤보의 선택 값과 표시 글자(`cd`, `nm`)
4. `dmScrgDdln`, `optDdln`의 마감 표시 값
5. 그리드 `grdMain`의 컬럼 속성(편집 가능 여부), 행 수, 선택된 행의 `getRowState` 값 종류
6. 어느 app 인스턴스가 지금 보이는 탭인지

선생님이 직접 보고 알려 주실 것(학생 정보는 빼고):
1. 본문을 쓰는 곳: 표 칸을 바로 고치는지, 행을 누르면 아래 입력칸에 열리는지
2. 입력칸 옆 바이트 표시 글(예: "n / 1500 byte")과 한도를 넘기면 어떻게 되는지
3. 이미 글이 있는 행이 표에서 어떻게 보이는지
4. [저장]을 눌렀을 때 뜨는 확인창과 알림 문구 그대로(이미 해 본 적이 있을 때만. 일부러 누르지 마세요)
5. 교과세특 화면의 입력칸 두 개(`txa1`, `txa2`)가 각각 무엇인지

- `verified`는 계속 `false`로 둔다. 7절의 값을 읽고 가상 화면까지 맞춘 뒤에만 `true`.

## 9. 실제 화면 읽기 결과 (2026-11-10, 읽기 전용)
방법: 크롬(Claude in Chrome)으로 나이스 화면을 열어 [조회]까지만 하고, 확장 [값 읽기]와 같은 읽기 전용 코드를 돌려 조건 값, 행 상태 개수, 길이 비교, 입력칸 상태를 읽었다. 입력, 저장, 삭제 등은 하지 않았고 학생 이름·본문 글자는 기록하지 않았다. 아래 값은 한 학급(3학년 반) 기준 예시다. 학교 코드 등 학교를 알 수 있는 값은 적지 않았다.

### 9-3. 마감 상태
- `dmScrgDdln`: `scrgClsDdlnYn`(학급 마감)=`N`, `scrgDdlnCfmtnYn`(확정)=`N`, `ddlnYn`=`N`. 교과세특은 `dmCheckTeukDesc.ddlnYn`=`N`. 동아리는 행마다 `scrgClsDdlnYn`=`N`, `scrgRfltYn`(학생부 반영 여부)=`N`.
- 확장은 입력 전에 이 값이 모두 `N`인지 확인하고, 하나라도 `Y`이면 입력하지 않는다. 동아리는 행의 `scrgRfltYn`이 `Y`인 학생도 건너뛴다.

### 9-4. 바이트 규칙 (실측)
- 나이스 `length` 열(자율 화면): 표본 7개 전부 **한글 3, 그 밖 1, 줄바꿈(LF) 1**과 일치. 줄바꿈이 2개 들어 있는 글에서 `length`=657, 줄바꿈 1바이트 계산=657, 2바이트 계산=659 → **줄바꿈은 1바이트**. 웹앱 `bytes.js`와 같은 규칙이다. 나이스 데이터셋의 줄바꿈은 `\n`(LF)만 있었고 `\r`은 없었다.
- 화면 안내문: "글자수는 Byte로 계산되며 한글은 3Byte, 영문·띄어쓰기는 1Byte". 교과세특 안내: "입력글자수의 단위는 Byte (한글 3, 영문/숫자 1)", "**1, 2학기 합쳐서 500자까지** 입력 가능", "위탁교 학생은 1·2학기 byte가 자동 합산되지 않음".
- `length` 열은 자율에서만 채워져 있고, 진로·행특·동아리는 비어 있거나 0이다 (화면의 글자수 표시는 화면이 직접 계산). 따라서 확장은 `length` 열에 의존하지 않고 우리 계산으로 검사한다.
- 화면의 한도 표시: 자율 `N / 1500 Byte`, 진로 `N / 1500 Byte`, 행동특성 `N / 900 Byte`. 동아리는 이 학급에서 표시를 확인하지 못했다. **웹앱 기본 한도(자율·진로·동아리 1500, 행특 900)는 화면 표시와 일치**한다.
- 교과세특은 한도가 **학생마다 다르다**: 각 행에 "일반 N / (입력 가능 Byte)"와 "영재 N / 1500 Byte" 두 줄이 있고, 일반의 가능 Byte는 1학기에 이미 쓴 만큼 줄어 있다(조회한 29명 모두 1500 미만, 902~1500). 이 값은 데이터셋 `dsGridMain.othSemInputLen01`(일반 가능 Byte), `othSemInputLen02`(영재, 1500)에 들어 있다. `inputCanLeng`, `inputLen`, `totalLength`는 조회 직후에는 비어 있거나 0이었다.
  - 웹앱 영향: 교과세특은 '과목 1500 byte' 한도 하나로 검사하면 2학기 글이 1학기 글 때문에 넘칠 수 있다. 나이스에 넣기 전에 `othSemInputLen01`로 학생별 가능 Byte를 읽어 비교해야 한다 (확장 쪽 검사).

### 9-5. 입력 방식에 관한 단서
- 본문은 표 안의 **칸 편집기(텍스트 영역)**로 쓰는 화면이다 (자율, 진로, 행특, 동아리 모두 학생마다 본문 칸이 있음). 입력칸 컨트롤(`txaSpeclActSpablMteCn`, `txaGnrlz`, `txa1`, `txa2`)은 `enabled`=true, `readOnly`=false이고 `maxLength`는 자율·동아리·교과세특 -1(제한 없음), 행특 1500, 진로 희망분야(`txaHopRealm`) 150이다. `bind` 계열 메서드는 없다.
- 조회 직후 모든 행의 `getRowState`는 `1`(변경 없음). 저장 판정은 출결 확장과 같이 '행 상태가 모두 1로 돌아옴'을 쓰면 된다.
- 표(`grdMain`)에는 `selectRows`, `getCellValue`, `focusCell`, `isEditing`, `getEditRowIndex` 등이 있고, 데이터셋에는 `getRowState`, `setRowState`, `commit`, `revert`, `isModified` 등이 있다. **값을 넣는 방법(데이터셋 `setValue`가 화면 칸에 반영되는지, 반영 뒤 행 상태가 4(수정됨)로 바뀌는지)은 쓰기 시험으로만 알 수 있다.** 학교에서 학생 1명, 저장 없이 시험하고 [조회]로 되돌린다.

### 9-6. 아직 확인하지 못한 것
- 저장 확인창과 알림 문구: 나이스 안내 메시지 데이터(`dsExMessage`)는 ID(`SW-SDL-xxxx`)만 있고 문구는 서버에서 받아서 읽을 수 없다. 첫 저장 시험에서 확장이 문구를 그대로 보여 주고 멈추므로 거기서 확정한다 (예상 문구는 출결과 같은 "저장하시겠습니까?"/"저장했습니다." 이지만 확인 전에는 가정).
- 값 넣기가 화면 칸과 바이트 표시에 반영되는지(위 9-5).
- 동아리 화면의 바이트 한도 표시.
- 화면 제목(`optTit`)과 보이는 탭 구분: 여러 화면이 열려 있을 때 어느 인스턴스가 지금 보이는 탭인지는 `getAllRunningAppInstances` 순서(마지막에 연 화면이 뒤)로 판단했다. 확장은 같은 app.id가 여러 개이면 마지막 인스턴스를 쓴다.
