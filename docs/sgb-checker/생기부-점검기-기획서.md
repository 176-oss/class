# 생기부 점검기 기획서 (v0.4.1, 확정)

작성일: 2026-11-08 (v0.1~v0.3) / 2026-11-08 오후 (v0.4 확정: 고등학교판 반영, 추가 기능 선택, 항목별 점검) / v0.4.1: API 키를 작성 도우미와 함께 쓰기 (10-1절)
단계: 기획 확정 → 개발 (프롬프트: `생기부-점검기-클로드코드-프롬프트.md`)
관련 문서: `생기부-작성도우미-업그레이드-기획서.md`, `생기부-작성도우미-분석과-적용안.md`, `textgenerator-v2-수정지시서.md` (5장 API 키)
기준 자료: 2026학년도 학교생활기록부 기재요령 중학교판, 고등학교판 (17개 시도교육청). 쪽수는 책자에 인쇄된 쪽 번호. '중 18'은 중학교판 18쪽, '고 19'는 고등학교판 19쪽.

## 0. 결정 사항
- 주 기능: **다른 사람이 쓴 생기부를 점검**한다.
- 입력: 글 붙여넣기, 엑셀 올리기 둘 다. 엑셀은 **항목별 점검**이 기본 (2절).
- 중학교, 고등학교 모두 지원. 학교급에 따라 한도, 영역, 금지 항목이 바뀐다.
- 개선점과 수정 문구를 제안하고, 적용은 선생님이 문구마다 누른다.
- 점검기와 작성 도우미는 따로 만들고, 같은 주소의 임시 저장소로 서로 넘긴다.
- **API 키는 한 번만 넣는다.** 작성 도우미나 점검기 어느 쪽에서 저장해도 다른 쪽이 같은 키를 쓴다 (10-1절).
- 모든 문장은 **음슴체(명사형 어미)** 로 끝나고 **관찰자 시점**이어야 한다 (중·고 30, "서술형 문장은 명사형 어미로 종결").
- 맞춤법, 띄어쓰기(낱말 사이)는 AI로 처리한다. 네이버 검사기는 공식 API가 없어 쓰지 않는다.
- 추가 기능: A~G, I, L 채택 (9절). H, J, K는 이번 범위에서 뺀다.
- 학생 글은 저장하지 않는다. 페이지를 닫으면 사라진다.
- 디자인: 작성 도우미와 같은 토큰 (#6B4410, #C98A1B, #FBEFD5, 글자 #2E2418, 선 #E8DCC6, 경고 #B42318, 통과 #5B7A2E), 글꼴 IBM Plex Sans KR 하나, 이모지 없음.

## 1. 점검 흐름
1. 학교급(중/고)과 학년을 고른다.
2. 항목을 고르고 엑셀을 올린다 (또는 글을 붙여넣는다).
3. 규칙 점검 결과가 바로 나온다. AI를 켰으면 맞춤법과 수정 문구가 이어서 나온다.
4. 학생별 상세에서 지적을 하나씩 보고 [적용], [예외 처리], [그대로 둠]을 고른다.
5. 점검 결과 보고서(엑셀)를 내려받아 작성한 선생님에게 돌려준다. 필요하면 수정본을 작성 도우미로 보낸다.

## 2. 항목별 점검 (엑셀)
항목마다 주로 틀리는 부분이 달라서, 항목을 고르면 그 항목 전용 점검표가 켜진다. 공통 점검(3절)은 모든 항목에 항상 적용된다.

### 2-1. 엑셀 형식
- 기본 양식(점검기에서 내려받기): `학번 | 이름 | 과목 | 내용`. 과목은 세특에서만 쓴다.
- 한 파일에 여러 항목을 넣고 싶으면 **시트 이름을 항목 이름**으로 한다 (자율, 동아리, 진로, 행특, 세특_국어 등). 시트 이름을 알아보면 항목을 자동으로 고르고, 모르는 이름이면 선생님에게 고르게 한다.
- 머리글 자동 찾기: 첫 10행 안에서 '학번', '번호', '이름', '성명', '과목', '내용', '특기사항', '세부능력', '종합의견'이 들어간 행을 머리글로 본다. NEIS에서 내려받은 파일처럼 위에 제목 줄이 있어도 된다.
- 학번은 5자리가 기본이지만, 번호만 있어도 점검은 한다 (점검에는 학번이 꼭 필요하지 않음).
- 빈 내용 행은 '미작성'으로 따로 센다.

### 3-1. 날짜 형식 (L)
- 하루: `2026.03.04.` (연.월.일. 끝에 마침표)
- 기간: `2026.03.04.-2026.07.08.` (사이는 하이픈, 공백 없음)
- 정량 표기: `(2026.03.04.-2026.07.08./5회)`, `학급회의(월 1회)`, `양성평등교육(4시간)` (중 77, 고 82 예시)
- 감지해서 바꿀 형식으로 제안하는 것: `2026. 3. 4.`, `2026-03-04`, `2026/3/4`, `3월 4일`, `2026.3.4`(마침표 없음, 한 자리 월일), 기간의 `~`, 물결표 앞뒤 공백.
- 연도가 없는 날짜(`3월 4일`)는 학년도를 붙여 제안하되 [적용] 전에 선생님이 확인한다.
- 문장 끝 날짜 뒤의 마침표 중복(`2026.03.04..`)도 잡는다.

## 5. 과장 표현 (C)
- 근거 없이 쓰기 쉬운 최상급·단정 표현을 찾아 '근거가 되는 활동이 글에 있는지 확인'을 요청한다 (중·고 19, 과장 기재 금지).
- 예: 탁월함, 완벽함, 최고, 최상, 천재적, 독보적, 압도적, 모든 면에서, 누구보다, 항상, 전혀.
- 오류가 아니라 '확인'으로 표시한다.

## 6. 화면 구성
1. **시작**: 학교급, 학년, 항목 고르기. [양식 내려받기]. 엑셀 올리기 또는 붙여넣기.
2. **결과 목록**: 학생별 통과 / 확인 / 오류. 항목별 지적 수. 필터(오류만, 바이트 초과만, 금지 내용만). 위쪽에 반 전체 요약(가장 많이 나온 지적 5개).
3. **상세**: 왼쪽 원문(문제 구절 밑줄, 색은 오류 빨강·확인 꿀색), 오른쪽 지적 목록. 지적마다 이유, 근거 쪽수(B), 바꿀 문장, [적용] [예외 처리] [그대로 둠].
4. **전후 비교 (I)**: 원문과 수정본을 나란히. 바뀐 부분만 표시(지운 글자 취소선, 넣은 글자 밑줄). 바이트 변화.
5. **보고서 (A)**: 엑셀 내려받기 (7절).
6. **설정**: 학교급 기본값, 영역별 한도, 학교 이름·별칭·축제명, 금지 목록 보기, AI 사용 여부와 API 키(작성 도우미와 함께 씀).

## 7. 점검 결과 보고서 (A)
- 시트 1 '요약': 항목, 학생 수, 통과·확인·오류 수, 많이 나온 지적.
- 시트 2 '학생별': 학번, 이름, 항목(과목), 바이트/한도, 지적 수, 지적 내용(한 칸에 줄바꿈으로), 근거 쪽수, 제안 문구, 예외 처리와 사유.
- 시트 3 '수정본': 학번, 이름, 원문, 적용한 수정본.
- 보고서에는 학생 이름이 있으므로 '교내에서만 주고받으세요' 안내를 띄운다.

## 8. 예외 처리 (G)
- 지적마다 [예외 처리]를 누르고 사유를 고른다 (교육관련기관임, 고유명사임, 학교 기준상 허용, 직접 입력).
- 예외 처리한 지적은 결과 목록에서 회색으로 남고 보고서에도 사유와 함께 남는다.
- 저장하지 않으므로 페이지를 닫으면 사라진다. 보고서에 기록이 남는다.

## 10. AI
- Gemini를 브라우저에서 직접 호출. 키는 `x-goog-api-key` 헤더.
- 보내는 것: 점검할 글, 항목, 학교급. 이름·학번은 보내지 않고 글 안의 명단 이름은 '학생'으로 가린다.
- AI가 하는 일: 맞춤법·띄어쓰기, 영역 적합성(D), 나열식(E), 지적된 문장의 수정 문구.
- 수정 문구 원칙: 원문에 있는 사실만, 지어내거나 부풀리지 않음, 명사형 어미, 관찰자 시점, 마침표, 바이트 한도 안.
- AI 수정 문구는 규칙 점검을 다시 통과해야 보여 준다. 통과 못 하면 '자동 제안 없음'.
- AI 제안을 적용할 때 '학생의 실제 활동과 맞는지 확인했습니다'를 처음 한 번 확인받는다 (중·고 19, AI 생성 자료를 그대로 입력 금지).
- AI는 설정에서 켠 경우에만. 학교 개인정보 지침을 확인한 뒤 켜도록 안내한다. 꺼져 있어도 규칙 점검은 모두 동작한다.
- 응답은 JSON, 화면에는 `textContent`로만.

### 10-1. API 키 함께 쓰기 (작성 도우미와 공유)
두 도구가 같은 주소(`https://176-oss.github.io`)에 있으므로, 브라우저가 같은 저장 공간을 보여 준다. 그래서 키를 한쪽에서만 넣으면 된다.
- **공용 키 자리**: localStorage `class:gemini-key` 하나. 값은 `{ key, savedBy: 'textgenerator-v2' | 'sgb-checker', savedAt }`.
- **점검기에서 키를 찾는 순서**: ① `class:gemini-key` ② 작성 도우미가 지금 키를 저장하는 자리(작성 도우미 코드에서 확인, 읽기만) ③ 없으면 키 입력 칸.
- 찾으면 설정에 '작성 도우미에서 저장한 키를 쓰는 중입니다 (끝 4자리 ****1234)'라고 보여 주고 [다른 키 넣기] [이 브라우저에서 키 지우기]를 둔다. 키 전체는 화면에 보이지 않는다.
- 점검기에서 '이 브라우저에 저장'으로 넣은 키는 `class:gemini-key`에 저장한다. 작성 도우미도 이 자리를 읽고 쓰게 고친다 (작성 도우미 후속 작업, 프롬프트 C).
- '이번에만 사용'은 그 탭에서만 쓰고 저장하지 않는다. 이때는 공유되지 않는다.
- [키 지우기]는 공용 자리에서 지운다. 화면에 '작성 도우미에서도 지워집니다'라고 알린다.
- 다른 PC에서 다시 넣지 않아도 되는 기능(드라이브에 키 저장)은 작성 도우미에만 있다. 작성 도우미에서 드라이브의 키를 불러오면 공용 자리에도 써 두므로, 점검기도 그 PC에서 바로 쓸 수 있다.
- 주의: 같은 주소의 모든 앱이 이 키를 읽을 수 있다. 그래서 학생 제작 코드는 이미 다른 주소로 분리했고, 이 주소의 앱은 innerHTML 금지와 외부 코드 내장 규칙을 지킨다. 결제가 연결되지 않은 무료 키를 쓰고, AI Studio에서 키 제한(웹사이트 `https://176-oss.github.io/*`, API는 Generative Language API만)을 걸도록 안내한다.

## 11. 작성 도우미와 연결
- 같은 주소(176-oss.github.io)의 localStorage 키 `sgb-handoff`에 한 번 쓰고, 상대 페이지가 읽은 뒤 바로 지운다. 5분 지나면 지운다 (새 탭으로 열리므로 sessionStorage는 공유되지 않음).
- 점검기 → 작성 도우미: [작성 도우미에서 고치기]. 학번, 항목, 과목, 글.
- 작성 도우미 → 점검기: [점검하기]. 작성 도우미 쪽 버튼은 작성 도우미 후속 작업(프롬프트 C)에서 붙인다.
- 주소창에 글을 넣지 않는다.
